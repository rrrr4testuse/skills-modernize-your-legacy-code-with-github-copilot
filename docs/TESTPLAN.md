# COBOL Account Management Test Plan

This plan describes the behavior implemented by the current COBOL application. Unless a case says otherwise, start a fresh process for the pre-condition; the balance is held in memory and starts at `1000.00` each time the program initializes. Run cases that contain multiple menu actions in the order shown. “Actual Result” and “Status” are left for the tester to complete.

| Test Case ID | Test Case Description | Pre-conditions | Test Steps | Expected Result | Actual Result | Status (Pass/Fail) | Comments |
|---|---|---|---|---|---|---|---|
| COB-001 | Initialize account balance | Start a fresh application process. | 1. Select `1` (View Balance). | The application displays `Current balance: 001000.00`; the initial balance is 1000.00. | Not executed | Not run | The balance is initialized in `DataProgram` working storage. |
| COB-002 | View the current balance | Start a fresh application process. | 1. Select `1` (View Balance). | The application reads and displays the current balance, initially 1000.00, then returns to the menu. | Not executed | Not run | Verifies the `TOTAL` operation and `READ` data operation. |
| COB-003 | Credit a whole-dollar amount | Start a fresh application process with balance 1000.00. | 1. Select `2` (Credit Account). 2. Enter `50`. 3. Select `1` (View Balance). | The application confirms the credit and displays the new balance of 1050.00. The subsequent balance inquiry also displays 1050.00. | Not executed | Not run | Verifies that a credit updates the shared in-memory balance. |
| COB-004 | Credit an amount containing cents | Start a fresh application process with balance 1000.00. | 1. Select `2`. 2. Enter `25.50`. 3. Select `1`. | The application confirms the credit and displays a balance of 1025.50. The subsequent inquiry displays the same balance. | Not executed | Not run | Confirms two-decimal-place amounts are used. |
| COB-005 | Debit less than the current balance | Start a fresh application process with balance 1000.00. | 1. Select `3` (Debit Account). 2. Enter `100`. 3. Select `1`. | The application confirms the debit and displays a new balance of 900.00. The subsequent inquiry displays 900.00. | Not executed | Not run | Verifies sufficient-funds debit behavior and persistence within the process. |
| COB-006 | Debit the exact current balance | Start a fresh application process with balance 1000.00. | 1. Select `3`. 2. Enter `1000`. 3. Select `1`. | The debit is allowed because the balance is greater than or equal to the debit amount. The new balance is 0.00 and the subsequent inquiry displays 0.00. | Not executed | Not run | Verifies the inclusive sufficient-funds boundary. |
| COB-007 | Reject a debit greater than the current balance | Start a fresh application process with balance 1000.00. | 1. Select `3`. 2. Enter `1000.01`. 3. Select `1`. | The application displays `Insufficient funds for this debit.` The balance remains 1000.00, as confirmed by the subsequent inquiry. | Not executed | Not run | Verifies no write occurs when funds are insufficient. |
| COB-008 | Debit an amount containing cents | Start a fresh application process with balance 1000.00. | 1. Select `3`. 2. Enter `10.25`. 3. Select `1`. | The application confirms the debit and displays a new balance of 989.75. The subsequent inquiry displays 989.75. | Not executed | Not run | Confirms cents are retained during subtraction. |
| COB-009 | Handle an invalid menu choice and continue | Start a fresh application process. | 1. Enter `5` at the menu. 2. Select `1`. 3. Select `4` (Exit). | The application displays `Invalid choice, please select 1-4.`, shows the menu again, then displays the initial balance after choice `1`. Choice `4` exits with the goodbye message. | Not executed | Not run | Choice field is one digit; this tests an out-of-range numeric menu value. |
| COB-010 | Exit the application | Start a fresh application process. | 1. Select `4` (Exit). | The application displays `Exiting the program. Goodbye!` and terminates without another menu. | Not executed | Not run | Verifies the normal exit path. |
| COB-011 | Credit zero | Start a fresh application process with balance 1000.00. | 1. Select `2`. 2. Enter `0`. 3. Select `1`. | The application accepts the amount, confirms the credit, and the balance remains 1000.00. | Not executed | Not run | There is no explicit zero-amount validation. Confirm the runtime accepts this input. |
| COB-012 | Debit zero | Start a fresh application process with balance 1000.00. | 1. Select `3`. 2. Enter `0`. 3. Select `1`. | The application accepts the amount, confirms the debit, and the balance remains 1000.00. | Not executed | Not run | There is no explicit zero-amount validation. Confirm the runtime accepts this input. |
| COB-013 | Characterize negative credit input | Start a fresh application process with balance 1000.00. | 1. Select `2`. 2. Enter `-10.00`. 3. Record the runtime response and then select `1` if the program continues. | The source contains no explicit negative-amount validation. The exact result of accepting a negative value into the unsigned numeric `AMOUNT` field is runtime/input dependent and is not specified as a business rule. | Not executed | Not run | Stakeholders should decide whether negative credits must be rejected before defining the required result. |
| COB-014 | Characterize negative debit input | Start a fresh application process with balance 1000.00. | 1. Select `3`. 2. Enter `-10.00`. 3. Record the runtime response and then select `1` if the program continues. | The source contains no explicit negative-amount validation. The exact result of accepting a negative value into the unsigned numeric `AMOUNT` field is runtime/input dependent and is not specified as a business rule. | Not executed | Not run | Stakeholders should decide whether negative debits must be rejected before defining the required result. |
| COB-015 | Confirm balance lifetime and reset | Complete a credit or debit in one application process, then terminate it and start a fresh process. | 1. In the first process, credit 50.00 and verify 1050.00. 2. Exit. 3. Start a new process and select `1`. | The first process shows 1050.00 after crediting. The fresh process starts at 1000.00; transactions are not persisted across process restarts. | Not executed | Not run | Balance storage is in working storage, not a file or database. |
